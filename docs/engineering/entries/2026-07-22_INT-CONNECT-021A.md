# 2026-07-22 — INT-CONNECT-021A

## Objective

Repair modern CLIENT connection behavior, explicit disconnect, launcher presentation, final APK packaging, SERVER registry persistence diagnostics, and duplicate-device registration caused by installation-centric identity.

## Facts

- CLIENT auto-connect preference persisted but the modern Core shell did not execute launch auto-connect.
- Connected CLIENT lacked an explicit disconnect action.
- Connecting label wrapped in the two-column control row.
- Android App info resolved the full-color dragon while the launcher still used a fallback/themed presentation.
- GitHub artifacts exposed two installable APKs.
- SERVER showed two durable rows for the same physical phone, one online and one offline.

## Engineering decisions

- Physical-device binding, installation identity, registration identity, live presence, proof, and trust remain separate.
- Device deduplication uses a privacy-preserving binding; raw invasive hardware identifiers are prohibited.
- Installation identity is lineage, not the physical-device primary key.
- Intentional disconnect preserves registration.
- Duplicate rows are superseded/archived, not destructively deleted.
- Build outputs are authoritative; APK_DOWNLOAD is fallback only.
